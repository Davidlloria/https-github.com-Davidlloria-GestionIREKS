COMPORTAMIENTO FUNCIONAL ACTUAL
-------------------------------

- El dashboard carga datos agregados desde CustomerDashboardService.load_snapshot().
- La fecha de cabecera usa el formato largo en español: "jueves, 23 de julio de 2026".
- El botón "Nueva actividad" abre DashboardAgendaDialog en modo alta.
- El botón "Ver agenda completa" abre DashboardAgendaOverviewDialog.
- El botón "Editar" de cada tarjeta abre DashboardAgendaDialog sobre la actividad seleccionada.
- Los botones laterales Agenda / Almacen / Pedidos / Ventas son placeholders y muestran un QMessageBox informativo.
- La tabla de clientes a reactivar mide la variación principal en kg y colorea el signo.
- Las tablas del dashboard son de solo lectura, con selección por fila y sin edición directa.

GEOMETRÍA ACTUAL
----------------

- dashboardSidebar tiene ancho fijo de 188 px.
- dashboardContent reparte el resto del ancho disponible sin splitter visible.
- La fila KPI usa cuatro tarjetas en una rejilla de una sola fila.
- Las filas media e inferior usan proporción 5:3 entre bloque izquierdo y derecho.
- dashboardKpiIcon mide 64 × 64 px.
- Los iconos KPI renderizados se centran dentro de un área interna de 46 × 46 px.
- El calendario emergente configurado para las fechas del dashboard tiene tamaño mínimo 340 × 272 px.

RELACIÓN CON BACKEND / DATOS
----------------------------

- DashboardPage no depende del frontend React.
- CustomerDashboardService aporta los KPIs, agenda de hoy, próximos vencimientos, clientes a reactivar y agenda por isla.
- CustomerService se usa para cargar clientes y para alta, edición y borrado de actividades de agenda.
- La agenda del dashboard trabaja directamente contra la base local desde PySide6/backend.
